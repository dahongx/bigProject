# CNC-RAG评测场景设计

本设计继承量子物理FAQ项目中“下界—噪声—RAG—上界”的实验思想，但不沿用含义混乱的AF编号。

## 生成层场景

| 场景ID | 输入上下文 | 研究目的 |
|---|---|---|
| `G0_no_context` | 无外部文档 | 测量LLM先验知识下界及幻觉倾向 |
| `G1_noisy_context` | 黄金证据与受控干扰片段 | 测量模型抵抗无关/冲突上下文的能力 |
| `G2_retrieved_context` | 指定检索配置返回的片段 | 测量完整RAG效果 |
| `G_oracle_context` | 人工标注黄金证据 | 测量检索完全正确时的生成上界 |

`G1_noisy_context`的干扰比例、来源和冲突类型必须由配置明确生成，不能为每个问题随意拼接不同长度的文档。

## 检索层配置

| 配置ID | 召回与处理 |
|---|---|
| `R0_bm25` | BM25 |
| `R1_dense` | 向量检索 |
| `R2_hybrid_rrf` | BM25 + 向量 + RRF |
| `R3_hybrid_metadata` | R2 + 型号/系统/版本元数据约束 |
| `R4_full` | R3 + Cross-Encoder重排 |

所有配置使用同一语料版本、同一测试问题和同一证据ID。分别报告Recall@k、Hit@k、MRR、nDCG@k和延迟。

## 语音查询层配置

| 配置ID | 查询输入 |
|---|---|
| `Q0_text_gold` | 人工标准文本 |
| `Q1_asr_raw` | ASR原始文本 |
| `Q2_lexicon` | 词表候选规范化 |
| `Q3_retrieval_constrained` | 领域检索辅助、带置信度的受约束规范化 |

语音实验除CER/WER外，必须报告术语准确率、代码完全匹配率、过度纠错率，以及各查询配置下的检索和回答变化。

## 公平比较约束

1. 同一组对比使用完全相同的问题ID；
2. 请求失败不得静默跳过，需记录失败原因并同时报告成功率；
3. “传统RAG”和“完整RAG”必须使用各自独立定义的检索配置；
4. 生成模型、温度和Prompt保持固定时才能归因检索模块；
5. 检索实验优先于生成实验，避免用LLM评分掩盖召回错误；
6. 自动裁判需要用人工子集校验一致性；
7. 无答案问题单独评价拒答，不能混入普通Recall平均值。
