
# 后续实施步骤与阶段验收清单

本清单在导师确认课题边界后执行。原则是先数据与文本RAG、再语音、最后硬件；每一阶段都保留输入、输出、配置和指标，保证论文实验可复现。

## 阶段0：导师确认与需求冻结

任务：

1. 确认最终题目、研究对象和知识范围；
2. 确认不做知识图谱，不做机床控制；
3. 确认硬件只作为语音交互验证平台；
4. 确认可使用的数控系统、设备型号和文档来源；
5. 确认学校对开题、数据规模、中期检查和成果形式的要求。

验收物：一页课题确认记录，包括题目、三项研究内容、实验范围和导师修改意见。

## 阶段1：文献精读与研究问题固化

任务：

1. 精读朱鹏丞《基于自然语言处理的煤矿调度语音智能处理与交互研究》，重点记录语音纠错、RAG实验、系统实验和章节结构；
2. 精读李华健《基于动态建模的自适应检索增强生成方法研究》，重点记录问题定义、基线、指标和消融组织；
3. 从其余论文中只提取文档分块、评价指标和系统写法，知识图谱不进入实现；
4. 建立文献阅读表：研究问题、数据集、方法、基线、指标、优点、局限、可借鉴内容。

验收物：相关工作矩阵、研究问题最终版、技术路线图和实验矩阵初稿。

## 阶段2：数据与评测集建设

任务：

1. 选择一套主数控系统或明确的设备文档集合，避免不同厂商版本无约束混用；
2. 建立原始文档清单，记录名称、来源、型号、版本、日期、许可和用途；
3. 实现PDF文本、标题、页码、表格及代码条目解析；
4. 设计分块方案和元数据字段；
5. 建立术语、同义词、字母数字组合、G/M代码、参数和报警代码词表；
6. 人工编写并复核测试问题，保存标准答案和证据位置；
7. 将训练/开发材料与最终测试集隔离，防止调参污染。

建议先做小规模闭环：3至5份文档、100个左右问题。流程稳定后再扩充，最终规模由文档可得性和导师要求确定。

验收物：数据卡、文档清单、解析结果、词表、测试集和人工标注规范。

## 阶段3：纯文本RAG基线

任务：

1. 实现统一文档接口和索引构建流程；
2. 建立BM25基线；
3. 建立向量检索基线；
4. 建立BM25与向量融合基线；
5. 固定评价脚本，输出Recall@k、MRR和nDCG@k；
6. 保存每次实验的模型、参数、随机种子、数据版本和结果文件。

验收标准：同一配置可以一条命令重复构建索引和运行评测；能够解释每类问题的主要失败原因。

## 阶段4：核心方法实现与消融

任务：

1. 比较固定长度、标题层级和语义分块；
2. 加入型号、数控系统、版本和知识类别元数据约束；
3. 比较RRF与加权融合；
4. 加入Cross-Encoder重排序；
5. 实现证据引用、无答案拒答和版本冲突提示；
6. 逐项进行消融，不同时改变多个变量；
7. 进行问题类型分组和错误分析。

验收物：主结果表、消融表、案例分析、错误分类及相应图表。

## 阶段5：语音查询规范化

任务：

1. 先固定一个ASR方案，保留原始识别文本；
2. 设计包含专业术语、字母数字、代码和噪声条件的语音测试集；
3. 实现词表及检索辅助的查询规范化；
4. 对比规范化前后的CER/WER、代码准确率、检索指标和最终回答正确率；
5. 对低置信度代码加入复述确认，评估误纠正情况。

验收物：语音测试集说明、ASR基线、纠错对比、下游增益和失败案例。

## 阶段6：硬件端到端验证

任务：

1. 确认ESP32板卡、麦克风、功放/扬声器、按键和可选屏幕；
2. 单独跑通ESP32与语音网关之间的音频上行和下行；
3. 固定VAD、ASR和TTS，关闭无关模块；
4. 通过OpenAI兼容接口接入独立的数控RAG服务；
5. 实现按键说话、停止、重复和下一步；
6. 测量不同噪声下的识别、首响应时间、总响应时间和任务成功率；
7. 记录演示视频、系统日志和硬件连接图。

验收标准：可以稳定完成“提问—检索—带依据回答—语音播放”闭环；服务异常和无答案时有明确反馈；任何情况下均不向机床下发控制指令。

## 阶段7：论文写作与材料归档

任务：

1. 数据集确定后先写第3章；
2. 文本实验完成后写第4章；
3. 硬件闭环完成后写第5章；
4. 全部实验固定后写第6章；
5. 最后完成绪论、总结和摘要；
6. 对照实验日志逐表核验，避免论文数字与结果文件不一致；
7. 对开源代码、模型和数据逐项标注来源与许可证。

验收物：章节初稿、图表源文件、实验结果索引、引用清单、演示材料和最终论文。

## 实施中的停止线

出现以下情况时不继续叠加功能，应先解决当前问题：

1. 没有明确文档版本和证据位置时，不开始生成质量实验；
2. 文本RAG尚未形成可靠基线时，不把语音和硬件接入核心实验；
3. 核心指标没有显著或稳定改进时，不提前把研究点写成创新点；
4. 端到端错误无法分解到ASR、检索或生成模块时，不做总体结论；
5. 硬件工作开始挤占RAG核心实验时，硬件范围退回到按键说话和音频收发闭环。
