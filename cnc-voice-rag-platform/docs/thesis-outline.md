# 推荐论文大纲（适中工作量版）

更新日期：2026年8月13日

暂定题目：**面向数控加工现场的语音交互式检索增强知识服务研究**

## 一、总体取舍

论文采用“**一个主要方法、一个应用改进、一个验证系统**”的结构：

1. 主要方法：面向数控技术文档的结构与元数据约束混合检索；
2. 应用改进：面向CNC术语和代码的语音查询规范化；
3. 验证系统：基于小智服务端和ESP32的语音知识服务平台。

BM25、通用向量检索和重排序是对比基线或组成模块，不分别扩展成独立研究方向。当前不要求训练Embedding、LLM或ASR模型；如果主方法实验效果不足，再将轻量检索模型微调作为后备增强，不预先增加工作量。

## 第1章 绪论

### 1.1 研究背景与意义

- 数控现场知识分散在操作、编程、参数、报警、维护和安全文档中；
- 型号、系统版本、代码和专业术语使通用问答容易检索错误；
- 工人双手被占用时，语音交互具有现实价值。

### 1.2 国内外研究现状

1. 大语言模型与检索增强生成研究；
2. 专业文档结构化检索研究；
3. 工业领域智能问答研究；
4. 专业语音识别与识别后纠错研究；
5. 现有工作的不足。

### 1.3 研究内容

1. 构建数控技术文档知识库和可追溯评测集；
2. 研究结构与元数据约束的混合检索方法；
3. 研究CNC术语和代码的语音查询规范化方法；
4. 实现并验证ESP32语音知识服务系统。

### 1.4 技术路线与论文结构

本章主要参考一般硕士论文的绪论写法，不承担方法创新。

## 第3章 面向数控技术文档的结构与元数据约束混合检索方法

本章是论文的**主要方法章**，也是工作量和实验的重点。

### 3.1 问题定义与总体流程

定义输入查询、文档集合、相关证据片段和型号/版本约束，分析固定分块、单路检索及跨版本混检的问题。

### 3.2 数控技术文档预处理与评测集构建

1. 文档采集、去噪和版本登记；
2. 标题层级、页码、表格及代码条目恢复；
3. 固定长度分块与章节结构分块；
4. 型号、系统、版本、文档类别等元数据设计；
5. 问题、标准证据和可回答性标注；
6. 数据集划分和质量复核。

### 3.3 结构增强的知识单元表示

- 保留“文档—章节—子章节—正文”的路径；
- 为叶子片段补充标题路径或父章节摘要；
- 对代码表和参数表按完整条目保存；
- 讨论结构信息加入检索文本的位置和长度。

### 3.4 面向查询特征的混合召回

- BM25负责代码、参数、报警号和精确术语；
- 向量检索负责口语化及描述性问题；
- 根据查询中精确标识、自然语言描述和条件字段调整两路贡献；
- 采用固定RRF作为普通混合基线，以查询特征驱动的融合策略作为完整方法。

### 3.5 型号与版本元数据约束

- 明确出现的型号/版本采用硬过滤；
- 由上下文推测的条件采用软加权；
- 缺少会改变答案的条件时触发澄清；
- 不在相互冲突的版本之间拼接答案。

### 3.6 证据组织与回答生成

- 去重并补充必要父级上下文；
- 输出文档名、章节和页码；
- 证据不足或冲突时拒答/澄清；
- 生成模型只基于最终证据回答。

### 3.7 实验与结果分析

#### 3.7.1 实验设置

- 数据集、模型、参数和评价指标；
- 主要指标：Recall@5、MRR、nDCG@5、证据命中率；
- 补充指标：答案正确率/忠实性和检索时延。

#### 3.7.2 主对比实验

只保留5组左右，避免无意义堆实验：

1. BM25；
2. 通用向量检索；
3. BM25 + 向量固定RRF；
4. 固定RRF + Cross-Encoder重排（强基线，可视资源决定）；
5. 本文完整方法：结构增强 + 查询特征融合 + 元数据约束。

#### 3.7.3 消融实验

1. 去除标题层级/父级上下文；
2. 去除查询特征融合，退回固定RRF；
3. 去除型号与版本元数据约束。

#### 3.7.4 分类结果与错误分析

按代码类、描述类、步骤类和版本类问题报告结果，并分析检索失败案例。

## 第4章 面向CNC术语与代码的语音查询规范化方法

本章是**应用改进章**，规模小于第3章，不训练或修改ASR模型。

### 4.1 工业语音查询问题分析

- 字母、数字和中英文混合术语容易误识别；
- G/M代码、参数号和报警号容错空间小；
- ASR错误会继续传递到检索和生成环节。

### 4.2 CNC术语与易混淆表达资源构建

- CNC术语、代码、参数和报警号词表；
- 拼音、读音、字符和数字混淆形式；
- 术语适用的型号、系统及版本信息。

### 4.3 领域候选检索与受约束规范化

1. 定位ASR文本中的疑似术语和代码位置；
2. 从领域词表召回少量候选；
3. 综合字形/读音相似度、上下文和文档检索证据排序；
4. 输出原文、规范化文本和修改轨迹；
5. 低置信度关键代码不自动修改，要求用户确认。

### 4.4 语音查询实验

#### 4.4.1 数据与指标

- 约150～300条语音查询；
- 安静环境和一种可重复现场噪声；
- 术语准确率、代码完全匹配率、过度纠错率；
- 规范化前后的Recall@5及答案正确率。

#### 4.4.2 对比实验

1. 干净文本查询：性能上限；
2. ASR原始文本：语音基线；
3. 通用LLM直接纠错；
4. 本文领域候选约束规范化。

#### 4.4.3 消融与错误分析

- 去除文档检索证据；
- 去除低置信度确认；
- 分析未纠正和过度纠正案例。

## 第5章 语音交互式数控知识服务系统设计与验证

本章是**工程实现和落地验证章**，不再提出新的复杂算法。

### 5.1 系统需求分析

- 语音免手输入；
- 带出处的数控知识查询；
- 分步骤播报、重复、继续和停止；
- 不直接控制机床；
- 高风险操作提示。

### 5.2 系统总体设计

- ESP32语音终端；
- 小智语音网关；
- CNC-RAG服务；
- 文档知识库和实验日志。

### 5.3 系统关键模块实现

- 音频采集、传输、ASR和TTS；
- 查询规范化接口；
- 检索、证据生成和引用；
- 有限多轮语音交互。

### 5.4 系统验证

1. 功能测试：典型查询、无答案、版本冲突和安全问题；
2. 性能测试：各模块及端到端响应时间；
3. 任务测试：约30～50个代表性任务的完成率；
4. 可选小规模用户评价：易用性、准确性感知和信任度；
5. 典型案例与失败归因。

## 三、工作量边界

### 必做

- 一个可追溯的数控文档评测集；
- 一个结构与元数据约束的混合检索完整方法；
- 约5组主检索对比和3项关键消融；
- 一个轻量语音查询规范化方法及4组对比；
- 一个ESP32端到端验证系统。

### 可选增强

- Cross-Encoder重排；
- 小规模用户评价；
- 领域Embedding或重排模型微调；
- 更多噪声强度和更多硬件终端。

### 明确不做

- 知识图谱；
- 从头训练或大规模微调ASR；
- 通用大语言模型训练；
- NL2SQL、机床实时控制和传统传感器故障诊断；
- 将每个现成组件都包装为独立创新点。

## 四、建议的贡献表述

1. 针对数控技术文档结构明显且型号、版本敏感的特点，提出结构与元数据约束的混合检索方法，并建立可追溯到文档章节和页码的评测集；
2. 针对CNC术语及代码的语音误识别问题，提出基于领域候选和检索证据的受约束查询规范化方法，并验证其对下游检索问答的改善；
3. 设计语音交互式数控知识服务系统，通过ESP32平台验证方法的端到端可用性。

第1项是主要方法贡献，第2项是应用方法贡献，第3项是系统应用贡献。是否最终称为“创新点”，应以对比和消融实验结果为准。
